The problem

Merchants know checkout is critical, but:

  • They don’t know where in the flow they’re losing buyers
  • They don’t know what to change in checkout settings
  • Existing reports are static and hard to translate into action

Result

  • Missed revenue from avoidable drop offs
  • Underused capabilities (express checkout, branded checkout, coupons, etc.)
  • Support and AMs answering the same “why is my checkout not converting?” question

The solution

An AI Checkout Recommendation Agent that sits inside Checkout Settings.
From analytics and guesswork → to guided, data driven optimization.

My role

I was the UX Designer on a cross functional team, and designed the recommendation experience in Checkout Settings using the Wix Design System. Together with the PM, BA and developers, we framed the problem and use cases, shaped the Collect, Analyze, Recommend model, and kept every recommendation grounded in real store data.

Merchants didn't want another chart. They wanted the tool to do the thinking.

I started by looking at how Wix presents analytics today, to understand what a regular user actually sees.

Then we looked at competitors like Shopify, to see whether they offer similar tools and how they present them.

The assistant could offer general guidance, but struggled to turn store specific challenges into clear, actionable next steps. The opportunity was to move beyond advice and help merchants understand what to do next.

What is the Checkout Recommendation Agent?

A smart layer inside Checkout Settings that:

Insights

  • “Your largest drop off is at Customer Details.”
  • “Drop off here is higher than similar businesses.”

Recommendations

  • “Reduce required fields from 12 to 6.”
  • “Enable express checkout for mobile buyers.”

Actions

  • Go to Checkout Form
  • Enable Express Checkout
  • Review Payment Methods

The concept: data, insight, recommendation, action

A smart layer that runs in three steps:

01

Collect

Buyer, item, locale, industry, season, settings

Fields. "Company name is required, but most of your buyers are consumers."

02

Analyze

Against a data model and similar store benchmarks

Funnel. "30% drop at Customer Details, higher than similar stores."

03

Recommend

A concrete change to a specific setting

Configuration. "Express checkout isn't enabled."

Percentages are illustrative.

A key decision: one benchmarked number, one action

The goal wasn't to give merchants more information, but to help them identify where to focus. Each recommendation connected a store specific insight to a measurable benchmark, making the opportunity clear and the next step concrete.

I translated this principle into a reusable recommendation component. Every recommendation uses the same structure, so merchants learn to read it once and know how to act on it.

  • 1Tag: relevant area
  • 2Recommendation: suggested action
    • Title: the actual suggested action, which can remain relatively standard across users.
  • 3Reasoning (personalized): explains why this recommendation matters, using their data.
  • 4CTA
    • Let’s Do It: navigates to Aria and performs the action, the user only needs to approve.
    • Show Me How: navigates to the page and opens Aria with instructions.

Turning recommendations into action

The recommendations were directly related to checkout configuration, so I placed the agent inside Checkout Settings, alongside the settings it recommends changing. This keeps the guidance close to the controls merchants need to act on.

Iterations

1. Where should the recommendations live?

We explored several placements for the recommendations panel to find the right home for it. Placement mattered: if the panel was hidden away, most merchants would never see it, and the value would be lost.

2. How much data fits in one card?

Each recommendation carries a lot of data. We iterated on how to show it in a single card: enough to act on, relevant to the merchant, and short enough not to overwhelm.

Making AI trustworthy before it reaches merchants

The model reads the store's own data and returns structured recommendations. Before any of it reached merchants, we checked it in stages: manual review, then a model judging a sample of sites, then repeated runs on a larger group.

Every recommendation had to be short (action up to 80 characters, reason up to 160), grounded in the store's data, and prioritized: revenue first, then drop off, then friction.

Rollout plan

A gradual release, so the recommendations could be checked on real stores before reaching everyone.

  • ~10K Stores users
  • Run for ~2 weeks
  • Check that recommendations are created and look good, review results and make prompt improvements if needed.
  • Full Stores Rollout: Expand to all Stores users
  • Gradual Expansion: Roll out to additional verticals gradually
  • Automatic completion: The system detects when a recommended action was done, sends a signal back, and marks it as done on its own.

Reflection

The hardest part of this project was that everything was built on AI. We held weekly progress meetings to make sure we brought merchants the best experience and relevant information they could actually use, so that in the end they could improve their conversion.

Designing for AI taught me to design for output I can’t fully control.
